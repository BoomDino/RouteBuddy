A student ride-matching prototype

Plan the ride together, before everyone books alone.

CabPool helps students leaving from Bennett University find other people going to the same destination at a compatible time. It estimates the road distance, forms groups of up to four, and shows how a Rs. 10-per-kilometre fare is shared.

How CabPool works

The program is a local Python command-line app. Each ride request moves through destination lookup, time matching, fare calculation, and file storage. Here is what happens from the moment someone opens it.

01

Add a ride request

Enter the passenger's name, destination, preferred departure time, and time flexibility. Flexibility can be from 0 to 360 minutes. The program checks each field before saving the request. Time can be entered as 24-hour time or with AM/PM.

02

Find the destination

CabPool checks the supplied list of 1,000 places, which includes cities and towns, airports, rail and metro stations, and other destinations. Enter a list number or place name. When a place is listed, CabPool looks it up on the map and calculates a driving route from Bennett University. If it is not listed, the program asks for the road distance in kilometres.

03

Match by destination and time

When you choose “Match and show results,” requests are grouped by destination and ordered by preferred departure time. CabPool takes the earliest unassigned request as the start of a group. It adds another passenger only when that person's available time overlaps the group's current shared window. The shared window narrows each time someone joins, and the group stops growing at four passengers.

04

Suggest a departure time

Once a group is formed, CabPool suggests the midpoint of the time window that works for every passenger. Time windows can cross midnight. A request that cannot join a group of at least two is shown as unmatched.

05

Calculate and display the fare

The trip fare is based on its road distance, then divided equally among the passengers in that cab. The results show the destination, distance, suggested departure and shared time window, passenger names, full cab fare, each passenger's share, and estimated savings compared with travelling alone.

06

Save the information

Requests, including their distance and flexibility, are stored in requests.csv and loaded the next time the app starts. After matching, the cab groups and fare summary are stored in results.json. Geocoded locations and routed distances are cached in distance_cache.json, so a place does not need to be looked up again.

Where the distance and fare come from

Every catalog trip starts at Bennett University in Greater Noida. For a listed place, CabPool uses OpenStreetMap's Nominatim service to find its map coordinates, then asks OSRM for the driving-route distance. The list supplies destination names; the road distance is looked up when a request is entered and cached locally.

Listed destination

Choose its list number or name. CabPool geocodes the place, routes from Bennett University, and displays the map match and calculated distance.

Unlisted destination

Enter the road distance from Bennett University manually. The same fare rate is used for manual and map-calculated distances.

cab fare = road distance in km × Rs. 10
fare per passenger = cab fare ÷ passenger count
group savings = (passenger count − 1) × cab fare

Example: a 20 km trip with four passengers

The cab fare is 20 × Rs. 10 = Rs. 200. Each passenger pays Rs. 200 ÷ 4 = Rs. 50. If each passenger travelled alone at the same rate, the group would spend Rs. 800; sharing the cab saves Rs. 600 in total.

Distances are routes to a mapped point, which may not be the exact entrance. They are estimates based on mapped roads, not live traffic or a taxi-company quote. Map lookup requires an internet connection. If the map service cannot find a route, CabPool asks for the distance manually.

The five parts of the program

Input and validation

Collects a request and checks the name, destination, time, flexibility, and distance.

Matching engine

Uses a greedy grouping method to find requests with the same destination and a common time window.

Fare calculator

Applies Rs. 10 per kilometre, divides the cab fare evenly, and estimates pooled savings.

File storage

Loads and saves requests in CSV, results in JSON, and map distances in a local cache.

Output display

Prints each matched cab, its departure window and fare, plus any unmatched requests.

Run CabPool

Install Python 3, clone or download the repository, and open a terminal in the project folder. The app uses Python's standard library; map lookup needs an internet connection.

python3 cabpool_5_methods.py

Use 1 to add a request, 2 to review saved requests, 3 to match passengers and show fares, or 0 to exit. For catalog destinations, you can enter either the place name or its number in the supplied list.

What this prototype does and does not do

CabPool demonstrates request validation, destination lookup, time-window matching, distance-based fare splitting, and local persistence. The current fare model is a simple Rs. 10 per kilometre with no base charge, tolls, or waiting fees. The public map services are best-effort and rate-limited. CabPool does not book a vehicle, contact passengers, collect payment, or provide turn-by-turn navigation.
